# 핫딜 레이더

핫딜 커뮤니티(뽐뿌·아카라이브·퀘이사존·루리웹 등)에 올라온 딜을 모으고, **같은 제품이 다른 쇼핑몰에서 평균 얼마에 팔리는지** 다나와 판매처 가격으로 확인해서, **쇼핑몰 평균가보다 크게 싼 딜만** 골라 보여 주는 앱이에요.
커뮤니티에 아직 안 올라온 딜도 찾아요. 지켜보는 제품의 판매처 목록에서 한 쇼핑몰만 유난히 싸면 '가격비교 발굴' 딜로 띄워요.

서버 없이 GitHub만으로 돌아가요(무료). 한국 집 컴퓨터에서 돌릴 수도 있어요.

```
30분마다 (GitHub Actions 또는 내 컴퓨터)
  ① 커뮤니티 핫딜 게시판 8곳 읽기        RSS가 있으면 RSS, 없으면 게시판 첫 페이지 한 장
  ② 새 글 검증                          제목에서 쇼핑몰·가격·배송비를 읽고 → 다나와에서 같은 제품 찾기
                                        → 그 제품의 쇼핑몰별 가격으로 '다른 쇼핑몰 평균가' 계산 → 할인율
  ③ 지켜볼 제품 고르기 (하루 한 번)       config.json의 제품군 키워드로 다나와 검색
  ④ 가격비교 발굴                        지켜보는 제품의 판매처 가격을 돌아가며 확인 → 한 곳만 크게 싸면 딜
  ⑤ 앱 데이터 만들기 → 텔레그램 알림 → 앱 배포 (GitHub Pages)
```

## 핫딜 판단 기준

| 항목 | 계산 |
|---|---|
| **쇼핑몰 평균가** | 다나와 상품 페이지에 실린 **쇼핑몰별 가격의 평균**. 딜을 올린 쇼핑몰은 빼고, 중간값의 0.5배 미만·1.8배 초과(오등록·다른 구성)도 빼요 |
| **할인율** | (쇼핑몰 평균가 − 딜 가격) ÷ 쇼핑몰 평균가 |
| **핫딜** | 할인율이 앱 설정의 기준(기본 30%) 이상 |
| 판매처가 적을 때 | 평균을 낼 판매처가 3곳보다 적으면 **다나와 최저가**와 비교해요(더 보수적인 값). 앱에 ‘판매처 적음’으로 표시돼요 |
| 배송비 | 딜과 판매처 양쪽 배송비를 알면 **배송비 포함 금액끼리**, 모르면 **상품 가격끼리** 비교해요 |
| 수량이 다를 때 | ‘24병’ 딜과 ‘12개’ 상품처럼 수량이 다르면 **개당 가격**으로 맞춰요 |
| 가격 확인 필요 | 평균보다 60% 넘게 싸면 옵션가·리퍼·가격 오류일 때가 많아 기본으로 숨기고 알림도 보내지 않아요 |

**같은 제품 찾기**는 틀리게 맞추는 것보다 못 맞추는 쪽을 택했어요. 상품명 단어 일치, 모델 번호(RTX 5070 ≠ 5080, WH-1000XM5 ≠ XM6), 용량(1TB ≠ 2TB), 해외구매·벌크·리퍼 구분, 가격대를 함께 봐서 점수가 낮으면 '같은 제품 못 찾음'으로 두고 할인율을 내지 않아요.
다나와 검색 결과의 용량·구성 옵션(1TB/2TB, 자급제/벌크)이 따로 있으면 딜과 맞는 옵션을 골라 비교해요.

## 가져오는 곳

| 출처 | 게시판 | 읽는 방법 |
|---|---|---|
| 뽐뿌 | 뽐뿌게시판 (해외뽐뿌는 기본 꺼짐) | 공식 RSS |
| 루리웹 | 유저 예판 핫딜 | 공식 RSS |
| 쿨앤조이 | 지름/알뜰정보 | 공식 RSS |
| 다모앙 | 알뜰구매 | 공식 RSS |
| 퀘이사존 | 지름/할인정보 | 게시판 첫 페이지 |
| 아카라이브 | 핫딜 채널 | 게시판 첫 페이지 |
| 클리앙 | 알뜰구매 | 게시판 첫 페이지 |
| 에펨코리아 | 핫딜 | 게시판 첫 페이지 |
| **다나와** | 통합검색, 상품 페이지 | 검색 결과와 상품 페이지에 처음부터 실린 판매처 목록 |

G마켓·11번가·쿠팡·이마트몰·SSG닷컴·네이버 등 **각 쇼핑몰 가격은 다나와 판매처 목록으로** 받아요. 쇼핑몰마다 따로 긁지 않는 이유는 아래 ‘왜 이렇게 만들었나’에 있어요.

### 지키는 규칙
- 요청 전에 사이트의 **robots.txt**를 읽고, 허용된 경로만 요청해요. 다나와가 막아 둔 판매처 전체 목록(`/info/ajax/…`)은 쓰지 않아요.
- 같은 사이트에는 **Crawl-delay**(다나와 10초) 또는 설정한 간격 이상 쉬었다가 요청해요.
- 이름을 숨기지 않는 User-Agent(`HotdealRadar/2.0; personal price checker`)를 써요.
- 사이트가 막거나(403·429) 봇 확인 페이지가 나오면 **우회하지 않고** 그 사이트를 6시간 쉬어요. 앱 설정의 ‘출처와 수집 상태’에 표시돼요.
- 한 번 실행에 12분 넘게 쓰지 않아요. 게시판은 첫 페이지만 읽어요.

## 앱에서 할 수 있는 것

| 탭 | 기능 |
|---|---|
| 핫딜 | 쇼핑몰 평균가보다 내 기준 이상 싼 딜. 커뮤니티 딜/가격비교 발굴, 제품군으로 거르고 할인율·새로 뜬 순·반응순(추천·댓글)·가격으로 정렬. 지난 방문 뒤 새로 뜬 딜에 NEW |
| 커뮤니티 | 게시판 글 전부와 비교 결과(‘평균보다 36%↓’, ‘평균 수준’, ‘상품권이라 비교 안 함’, ‘같은 제품 못 찾음’). 게시판별 필터, 끝난 딜 숨기기 |
| 상세 | 딜 가격과 평균가, **쇼핑몰별 가격표**(딜과의 차이, 평균선), 최저가·평균가 **그래프**, 같은 딜이 올라온 게시판들, 같은 제품의 다른 글, **어떻게 비교했는지** |
| 검색 | 지켜보는 제품과 커뮤니티 글에서 찾기. 없는 제품은 다나와로 바로 연결 |
| 찜 | 제품 단위로 찜하고 목표가 설정. 진행 중인 딜과 다나와 최저가 중 싼 값으로 추적 |
| 설정 | 핫딜 기준(5~70%), 관심 제품군, 출처별 켜기·끄기와 **수집 상태**, 쇼핑몰 제외, 가격 확인 필요·끝난 딜 숨기기, 알림 기준 복사 |

같은 제품·같은 쇼핑몰 딜이 여러 게시판에 올라오면 하나로 합치고 올라온 곳을 모두 보여 줘요.
휴대폰에서 **홈 화면에 추가**하면 앱처럼 열리고, 인터넷이 끊겨도 마지막으로 받은 내용을 보여 줘요. 찜·설정은 그 기기에만 저장돼요.

## 설치 (GitHub, PC에서 10분)

1. GitHub에서 **New repository**로 저장소를 만들어요(예: `hotdeal-radar`). 무료 계정이면 **Public**이어야 GitHub Pages를 쓸 수 있어요.
2. 이 폴더의 파일을 모두 올려요. 웹에서는 **Add file → Upload files**에 폴더째 끌어다 놓으면 돼요. `.github` 폴더가 꼭 같이 올라가야 해요(숨김 폴더라 빠지기 쉬워요).
3. **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿔요.
4. **Actions** 탭 → 왼쪽 **핫딜 수집** → **Run workflow**. 5~12분 뒤 초록색 체크가 뜨면 성공이에요.
5. 앱 주소는 `https://<GitHub 아이디>.github.io/<저장소 이름>/`이에요. 휴대폰에서 열고 홈 화면에 추가하세요.
   - 아이폰: Safari 아래 공유 버튼 → **홈 화면에 추가**
   - 안드로이드: Chrome 오른쪽 위 ⋮ → **홈 화면에 추가** 또는 **앱 설치**

이후로는 30분마다 자동으로 돌아요. 수집 기록은 `data` 브랜치 하나에 덮어써서 저장소가 커지지 않아요.
첫 수집 전에는 앱이 **예시 데이터**로 움직여요(오른쪽 위에 ‘예시 데이터’ 표시).

> **GitHub 서버에서 막히는 사이트가 있을 수 있어요.** 일부 커뮤니티는 해외 클라우드 서버의 접속을 막아요. 앱 **설정 → 출처와 수집 상태**에서 ‘접속 차단됨’이 계속 보이면, 아래 ‘내 컴퓨터에서 돌리기’로 한국 인터넷에서 돌려 보세요.

## 텔레그램 알림 켜기 (선택)

새 핫딜이 뜨면 휴대폰으로 알림이 와요. 같은 딜은 한 번만 알리고, 그 뒤 3% 넘게 더 내려가면 다시 알려요.

1. 텔레그램에서 **@BotFather**에게 `/newbot`을 보내 봇을 만들면 **토큰**(`123456789:AA…`)을 줘요.
2. 만든 봇과 대화를 열고 아무 메시지나 보내요.
3. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates`를 열어 `"chat":{"id":` 뒤의 숫자(**채팅 id**)를 찾아요.
4. 저장소 **Settings → Secrets and variables → Actions → New repository secret**에 두 개를 만들어요.

| Name | Secret |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1단계의 토큰 |
| `TELEGRAM_CHAT_ID` | 3단계의 숫자 |

알림 기준은 `config.json`의 `alerts`에서 정해요. 앱 **설정 → 텔레그램 알림 → 지금 설정으로 알림 기준 복사**를 누르면 앱에서 고른 기준과 관심 제품군이 그대로 복사돼요.

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `alerts.threshold` | 30 | 쇼핑몰 평균가보다 이만큼(%) 이상 싼 딜을 알려요 |
| `alerts.categories` | [] | 비우면 모든 제품군, 넣으면 그 제품군만 (예: `["pc", "audio"]`) |
| `alerts.keywords` | [] | 이 단어가 이름에 들어간 딜은 `keyword_threshold`만 넘어도 알려요 (예: `["에어팟", "다이슨"]`) |
| `alerts.keyword_threshold` | 15 | 키워드 딜의 알림 기준(%) |
| `alerts.min_votes` | 0 | 커뮤니티 딜은 추천이 이만큼 이상일 때만 (추천 수를 모르는 게시판은 그대로 알림) |
| `alerts.max_per_run` | 10 | 한 번에 알릴 최대 개수 (넘친 딜은 다음 번에) |
| `alerts.renotify_drop` | 3 | 이미 알린 딜은 그때보다 이만큼(%) 더 내려가야 다시 알려요 |

## 설정 바꾸기 (`config.json`)

저장소 웹 화면에서 연필 아이콘으로 바로 고칠 수 있어요. 형식이 틀리면 다음 실행 때 Actions 기록에 어디가 틀렸는지 한국어로 나와요.

```json
{ "id": "pc", "name": "노트북·PC", "icon": "💻", "hue": 220,
  "keywords": ["노트북", "모니터", "그래픽카드"],
  "match_words": ["PC", "하드웨어", "노트북", "모니터", "SSD", "RTX"] }
```

- `keywords`: 이 제품군에서 **다나와에 검색해 지켜볼 제품**을 고르는 말이에요(키워드마다 상위 6개). 특정 제품을 꼭 지켜보려면 `"다이슨 에어랩"`처럼 모델명을 넣으세요.
- `match_words`: 커뮤니티 글을 이 제품군으로 분류할 때 보는 단어예요(게시판 분류명이나 제목에 들어 있으면).
- `id`: 앱 설정과 알림 설정에 저장되는 값이라 한 번 정하면 바꾸지 않는 게 좋아요. 영어 소문자·숫자로 써요.
- `watch`: 찜한 제품을 계속 추적하게 할 다나와 상품 번호 목록. 앱 **설정 → 찜한 제품 계속 추적하기**에서 복사할 수 있어요.

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `sources.<출처>` | true (해외뽐뿌만 false) | 읽을 게시판 켜기·끄기 |
| `community.keep_hours` | 72 | 게시판 글을 앱에 남겨 두는 시간 |
| `community.verify_overseas` | false | 해외 직구 딜도 국내 쇼핑몰 가격과 비교할지 |
| `danawa.min_delay_seconds` | 10 | 다나와 요청 간격(초). robots.txt의 Crawl-delay보다 짧게는 안 돼요 |
| `danawa.max_verifications_per_run` | 15 | 한 번에 검증할 새 글 수 (남은 글은 다음 번에) |
| `danawa.max_product_pages_per_run` | 20 | 한 번에 확인할 다나와 상품 페이지 수 |
| `danawa.recheck_hours` | 8 | 지켜보는 제품 가격을 다시 확인하는 간격 |
| `danawa.max_products` | 300 | 지켜보는 제품 최대 수 |
| `pricing.min_malls_for_average` | 3 | 평균가를 내는 데 필요한 판매처 수 |
| `pricing.suspicious_rate` | 60 | 이보다 크게 싸면 ‘가격 확인 필요’ |
| `pricing.match_min_score` | 0.62 | 같은 제품으로 볼 최소 점수(높일수록 깐깐) |
| `run.budget_minutes` | 12 | 한 번 실행에 쓸 최대 시간 |

실행 간격을 바꾸려면 `.github/workflows/collect.yml`의 `cron`을 고쳐요(분 단위 UTC, 예: `"7 * * * *"`는 매시 7분).

## 내 컴퓨터에서 돌리기

한국 인터넷에서 돌리면 해외 서버를 막는 사이트도 읽을 수 있어요. Python 3.10 이상이 필요해요.

```bash
pip install -r requirements.txt

python -m collector.run              # 수집 → 정리 → 알림 한 번
python -m collector.run --every 30   # 30분마다 계속 (켜 둔 동안. Ctrl+C로 멈춤)

python -m http.server 8000 -d docs   # 앱 보기 → http://localhost:8000
```

텔레그램 알림을 쓰려면 실행 전에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` 환경 변수를 넣어 주세요.
윈도우에서 컴퓨터를 켤 때마다 자동으로 돌리려면 **작업 스케줄러**에 `python -m collector.run`을 30분 간격으로 등록하면 돼요(시작 위치: 이 폴더).

## 사이트 화면이 바뀌었을 때

앱 **설정 → 출처와 수집 상태**에 ‘글을 못 읽음’이나 ‘형식 바뀜’이 뜨면 게시판 화면 구조가 바뀐 거예요. 다나와는 화면을 자주 바꿔서, 파서가 여러 방식을 차례로 시도하고 어떤 방식으로 읽었는지 기록해요.

```bash
python -m collector.probe all                    # 켜 둔 게시판 + 다나와 검색·상품 페이지를 한 번씩 읽고 결과 출력
python -m collector.probe source arcalive        # 게시판 하나
python -m collector.probe search "갤럭시 버즈3 프로"
python -m collector.probe product 12345678       # 다나와 상품 번호
python -m collector.probe match "[쿠팡] 삼성 990 PRO 2TB (189,000원/무료)"   # 제목 하나를 끝까지 검증
```

받은 원본 HTML은 `data/debug/`에 저장돼요. GitHub에서는 **Actions → 사이트 구조 점검 → Run workflow**를 누르면 같은 결과를 `probe` 파일로 내려받을 수 있어요. 고칠 곳은 `collector/community.py`(게시판)와 `collector/danawa.py`(다나와)예요.

## 왜 이렇게 만들었나

- **네이버 쇼핑 검색 API는 2026년 7월 31일에 종료**됐어요. 이전 버전은 이 API를 썼는데, 지금은 새로 키를 받을 수도 없어요. 네이버 쇼핑·스마트스토어는 robots.txt로 자동 수집을 막아 두어 직접 읽지 않아요.
- 쇼핑몰마다 따로 긁으면 로그인·봇 차단·약관 문제가 쌓이고 같은 제품 맞추기도 훨씬 어려워요. **다나와는 쇼핑몰별 가격을 한 페이지에 모아 두고, robots.txt가 검색과 상품 페이지 읽기를 허용**해요. 그래서 각 쇼핑몰 가격은 다나와 판매처 목록으로 받았어요.
- 쿠팡 파트너스 API는 승인과 호출 제한이 있어 기본으로 넣지 않았어요. 에누리는 robots.txt가 자동 수집을 막아 두었어요.

## 알아 둘 점

- 다나와 상품 페이지에 **처음부터 실린 판매처만** 읽어요(다나와가 막아 둔 전체 판매처 목록은 쓰지 않아요). 인기 상품은 판매처가 더 많을 수 있어요. 상세 화면에 ‘다나와 표기 판매처 N곳 중 M곳’으로 보여 줘요.
- 다나와에 없는 제품(PB 상품, 소규모 브랜드, 상품권·식권 등)은 비교할 수 없어 커뮤니티 탭에만 보여요.
- 카드 할인·쿠폰·멤버십가는 커뮤니티 글에는 들어 있고 다나와 가격에는 빠져 있을 때가 많아요. 그래서 할인율이 실제 체감보다 크게 나올 수 있어요.
- 같은 제품 맞추기는 틀릴 수 있어요. 상세 화면의 ‘어떻게 비교했나요’에서 다나와 상품명을 확인하세요.
- **개인 용도**로 쓰는 걸 전제로 만들었어요. 각 사이트의 이용약관은 자동 수집이나 재배포를 제한할 수 있으니, 다른 사람에게 공개하는 서비스로 키우거나 수집 간격을 크게 줄이기 전에 약관을 꼭 확인하세요. 사이트가 접속을 막으면 우회하지 말고 그 출처를 꺼 주세요.
- 저장소가 Public이면 `data` 브랜치의 수집 기록(게시글 제목·가격)도 공개돼요. 텔레그램 토큰은 Secrets에 있어 공개되지 않아요.
- GitHub 예약 실행은 서버 사정으로 늦거나 건너뛸 수 있어요. 60일 동안 저장소에 변화가 없으면 예약 실행이 멈추는데, 그때 오는 메일의 링크나 **Actions** 탭에서 다시 켜면 돼요.

## 파일 구조

```
config.json                   제품군·키워드·출처·계산·알림 설정
collector/
  http.py                     robots.txt·요청 간격·차단 감지를 지키는 HTTP 클라이언트
  community.py                게시판 8곳 읽기 (RSS·HTML)
  textnorm.py                 제목에서 쇼핑몰·가격·배송비·수량·모델 번호 읽기
  danawa.py                   다나와 검색·상품 페이지 읽기
  compare.py                  같은 제품 찾기, 쇼핑몰 평균가·할인율 계산
  collect.py                  수집 한 번 실행 (시간 예산 안에서)
  build.py                    앱 데이터 docs/data/deals.json 만들기
  notify.py                   텔레그램 알림
  run.py                      수집→정리→알림 한 번에 / 일정 간격으로
  probe.py                    사이트 구조 점검 도구
  store.py                    설정 검사·파일 저장·가격 기록
  mock.py                     네트워크 없이 시험하는 가짜 사이트·예시 데이터
docs/
  index.html                  앱 (deals.json이 없으면 data/demo.json 예시로 동작)
  data/demo.json              예시 데이터 (python -m collector.mock demo 로 다시 만듦)
  manifest.webmanifest, sw.js, icons/   홈 화면 앱·오프라인 지원
tests/                        파서·제목 해석·비교 계산·HTTP 규칙·전체 흐름 테스트 (fixtures/에 실제 화면 구조를 본뜬 파일)
.github/workflows/
  collect.yml                 30분마다 수집·알림·배포
  probe.yml                   사이트 구조 점검 (수동 실행)

data/ (data 브랜치 또는 내 컴퓨터)
  community.json              게시판 글과 검증 결과
  products.json               지켜보는 제품과 판매처 가격
  history/YYYY-MM.csv         날짜별 최저가·평균가 기록
  state.json, last_run.json   출처 상태, 검색 캐시, 마지막 실행 요약
  notified.json               이미 알린 딜
```
